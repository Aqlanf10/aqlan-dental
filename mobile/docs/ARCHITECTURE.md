# معمارية Mobile V2

## الطبقات

- `app/`: مسارات Expo Router فقط؛ كل شاشة تتحقق من حالة الجلسة.
- `src/components/`: عناصر بصرية صغيرة متوافقة مع اللغتين وإتاحة الاستخدام.
- `src/i18n/`: مصدر الترجمة الوحيد، اختيار اللغة المحفوظ، واتجاه RTL/LTR الديناميكي.
- `src/api/`: عنوان الخدمة، النقل، المهلة، تحليل الأخطاء والتحقق وقت التشغيل من الاستجابات.
- `src/auth/`: دورة حياة الجلسة والتخزين الآمن.
- `src/theme/`: ألوان ومسافات وخطوط موحدة لهوية العيادة.
- `src/errors/`: حاجز يمنع انهيار التطبيق كاملًا عند خطأ عرض غير متوقع.

## الجلسة والأمان

1. تسجيل الدخول عبر `POST /api/auth/mobile/login`.
2. حفظ access token وrefresh token وبيانات المستخدم في SecureStore المقيّد بالجهاز.
3. التحقق من الجلسة عبر `GET /api/auth/me` وتحميل `GET /api/auth/me/permissions` بالتوازي.
4. عند 401 أثناء الاستعادة فقط، يُستخدم `POST /api/auth/mobile/refresh-token` مرة واحدة ثم يعاد التحقق.
5. لا تعاد تلقائيًا عمليات الإنشاء أو التعديل، لمنع التكرار غير المقصود.
6. تسجيل الخروج المحلي نافذ حتى لو تعذر اتصال طلب الإلغاء بالخادم.

## الثنائية اللغوية

لا يُستخدم `I18nManager.forceRTL` لأنه يتطلب إعادة تشغيل. بدلًا منه يحدد `LocaleProvider` الاتجاه، وتضبط المكونات `flexDirection` و`textAlign` و`writingDirection` لحظيًا. يبقى اختيار اللغة محفوظًا في SecureStore.

## عقود البيانات

جميع استجابات المصادقة والصلاحيات من نوع `unknown` حتى تمر بالتحقق وقت التشغيل. لا يجوز الاعتماد على TypeScript وحده لاعتبار بيانات الشبكة صحيحة.

## سياسة بناء الوحدات

كل وحدة جديدة تمر بالمراحل: عقد API، حالات الشاشة، الصلاحيات، العربية والإنجليزية، التنفيذ، اختبار TypeScript، اختبار الترجمة، تصدير Android وiOS، ثم تجربة APK على هاتف حقيقي.
