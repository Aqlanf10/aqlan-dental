# تدقيق وحدة التقارير — REP-OPS

آخر تحديث: 2026-07-29
النطاق: `ReportsController`، `FinanceV3Controller.Reports`، صفحة `/reports` وصفحة `/reports/operations`.

## تصحيح خط الأساس

التحليل الأولي في هذا الفرع كان وثائياً فقط واحتوى استنتاجات غير دقيقة:

- `overdue-contracts` كان يعيد اسم المريض فعلاً؛ المشكلة أنه لم يكن تقرير أرصدة شاملًا حسب المريض والعملة.
- `financial` كان يعيد تفاصيل يومية، لكنه كان يجمع YER وSAR وUSD في رقم واحد ثم تعرضه الواجهة كـYER.
- صفحة `/reports/operations` كانت موجودة، لكنها كانت لوحة زحام/طابور وليست منشئ تقارير مرضى.
- واجهة `/reports` ربطت 14 أزرار تصدير، بينما الخادم وفر ثلاثة مسارات CSV فقط؛ أغلب الأزرار كانت تنتهي بـ404.

## ما نُفذ

أضيفت طبقة تقارير تفصيلية محمية بسياسة `ReportsAccess` ومقيدة بفرع المستخدم غير الإداري:

`GET /api/reports/operations/details`

المعاملات المشتركة: `type` و`from` و`to` و`page` و`pageSize`، إضافة إلى `absenceDays` لتقرير العائدين.

| النوع | الصفوف |
|---|---|
| `new-patients` | رقم المريض، الاسم، الهاتف، التسجيل، الطبيب، الزيارات |
| `treated-patients` | الزيارة، الطبيب، التخصص، التشخيص، العلاج المنفذ، الإغلاق |
| `income` | كل سند قبض، عملة القبض، المبلغ المحتسب، عملة الحساب، الطريقة والخدمة |
| `outstanding-balances` | المريض والعملة وإجمالي المطالبات والمدفوع والمتبقي |
| `treatment-progress` | إجمالي/مكتمل/قيد التنفيذ/متبقٍ، النسبة والخطوة التالية |
| `returning-patients` | الزيارة السابقة والعودة وفجوة الغياب والعلاج السابق والحالي |
| `ortho-cases` | الحالة والمرحلة والتقدم والزيارات والعقد والمدفوع والمتبقي |

التصدير `GET /api/reports/operations/export` يعيد CSV عربيًا بترميز UTF-8 BOM وبنفس أعمدة التقرير. أزيلت اتصالات الواجهة بالمسارات الوهمية، وبقيت أزرار الملخص مقيدة بمسارات حقيقية فقط.

## العملات

- التقرير المالي القديم أصبح يعيد `totalsByCurrency`.
- التجميع اليومي، حسب التخصص، وحسب طريقة الدفع يحمل `currency`.
- القيم القديمة المفردة بقيت للتوافق، لكنها YER فقط ولا تستخدمها الواجهة الجديدة كإجمالي متعدد العملات.
- تصدير الدفعات يتضمن عملة القبض، المبلغ المحتسب، وعملة الحساب.

## الزمن والصلاحيات

- المرضى الجدد يستخدمون `ClinicTimeProvider.ToUtcRange` لحدود يوم العيادة.
- الإداري يرى الفروع مجتمعة، والمحاسب غير الإداري يرى فرعه فقط، وغير الإداري بلا فرع يتلقى 403.
- الأطباء غير داخلين في `ReportsAccess` حالياً؛ لا توجد واجهة تقارير أسماء للأطباء حتى يقرر المنتج سياسة مستقلة.

## التحقق

- بناء API ناجح دون أخطاء أو تحذيرات.
- TypeScript ناجح.
- 12 اختبار backend تغطي العملات، الفروع، حدود اليوم، الأرصدة، العودة، العلاج، CSV والصلاحيات.
- 10 اختبارات frontend contract تغطي الأنواع، المسارات، الترقيم، العملات، وإزالة مسارات التصدير الوهمية.

## المتبقي خارج هذا التسليم

- تصدير PDF للتقارير التفصيلية (CSV منفذ).
- مقارنة آلية بالفترة السابقة؛ اختيار اليوم/الشهر/السنة/فترة مخصصة منفذ.
- اختبار بصري على Preview بعد رفع الفرع، قبل الدمج.
