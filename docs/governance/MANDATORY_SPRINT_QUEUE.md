# طابور السبرنتات الإلزامي — Mandatory Sprint Queue

**هذا الملف هو مصدر الحقيقة الوحيد لترتيب العمل على Aqlan Dental Pro.**
يلغي أي ترتيب سابق في ملفات الخطط التاريخية. الأدلة التفصيلية تبقى في
`docs/governance/SPEC_TO_CODE_TRACEABILITY.md` وملفات التدقيق والـPRs المرتبطة.

## القاعدة الإلزامية

1. قبل أي تطوير، اقرأ هذا الملف كاملًا.
2. أول عنصر بحالة `🔴 محجوب` أو `🟡 جاهز` أو `🔵 قيد التنفيذ` هو العمل الوحيد المسموح.
3. لا يجوز القفز لعنصر لاحق إلا لحادث إنتاج P0، تدقيق قراءة فقط، إكمال PR مفتوح، أو حل تعارض دمج.
4. كل PR تنفيذي يذكر رقم العنصر في العنوان، ويحدّث حالته عند تحقق معيار الخروج.
5. البنود المنجزة لا يعاد فتحها إلا بدليل ارتداد أو عطل إنتاجي جديد.

### ✅ SEQ-16 — منع الحالة الفارغة الكاذبة في عيادة الطبيب

- فشل التحديث الدوري بعد وجود بيانات لا يهدم مساحة الطبيب ولا يفقد الملاحظات السريرية غير المحفوظة؛ تبقى البيانات المخزنة ظاهرة.
- **معيار الخروج:** الاستجابة الناجحة الفارغة، والفشل الأولي، وفشل التحديث الخلفي مغطاة باختبارات ارتداد؛ Backend وFrontend وE2E وEncoding Guard خضراء، وملاحظة Codex P2 محلولة، ولا API أو schema أو تغيير في سير الزيارة.

### ✅ SEQ-17 — كشف حساب الطبيب غير المرتبط بسجل طبيب
- **PR:** #653.
- الحساب السريري غير المرتبط بـ`doctorId` لا يرسل طلب قائمة مرضى ولا يعرض «لا يوجد مرضى» الكاذبة، بل تظهر له رسالة إعداد عربية تطلب من المدير ربط الحساب من إعدادات المستخدمين والصلاحيات.
- بقي وضع Admin لعرض جميع الأطباء، وبقي الحساب المرتبط يرسل `doctorId` الصحيح دون تغيير في الوصول أو سير الزيارة.
- **معيار الخروج:** اختبارات الواجهة تغطي الحساب غير المرتبط، الحساب المرتبط، ورسالة الإصلاح؛ Frontend وBackend وE2E وEncoding Guard خضراء، ولا API أو schema أو auth DTO أو ربط تلقائي.

### ✅ SEQ-18 — إثراء استجابة إنشاء الموعد
- **PR:** #655.
- أصبحت معاملة إنشاء الموعد تحمّل علاقات `Patient` و`Doctor` و`Package` قبل الإرجاع، لذلك تحتوي الاستجابة الفورية أسماء العرض الصحيحة بدل القيم الفارغة.
- بقي فحص التعارض والقفل الذري كما هو، وتحميل العلاقات داخل المعاملة يمنع حفظ الموعد ثم إعادة 500 إذا فشل الإثراء.
- **معيار الخروج:** اختبار repository يبدأ بموعد يحوي المعرّفات فقط ويثبت تحميل بيانات المريض والطبيب؛ Backend وFrontend وE2E وEncoding Guard خضراء، ولا schema أو API أو قواعد حجز أو صلاحيات تغيرت.

### ✅ SEQ-19 — توحيد قائمة مواعيد اليوم مع تاريخ العيادة
- **PR:** #656.
- أصبحت `AppointmentRepository.GetTodayAsync` تستخدم `ClinicTimeProvider.ClinicToday()` بدل تاريخ خادم التشغيل، مع تاريخ صريح اختياري للاختبارات الحتمية.
- بقيت فلاتر الفرع والطبيب وترتيب الموعد والتحميل المسبق للمريض والطبيب دون تغيير.
- **معيار الخروج:** اختباران يغطيان التاريخ الصريح والافتراضي المهيأ؛ Backend وFrontend وE2E وEncoding Guard خضراء، ولا endpoint أو DTO أو صلاحيات أو قواعد حجز تغيرت.

### ✅ SEQ-20 — تنبيهات لوحة التحكم لا تختفي بصمت عند فشل التحميل
- **PR:** #657.
- **الدليل:** `frontend/src/components/dashboard/AttentionAlerts.tsx` يعيد `null` عند فشل `/api/dashboard/alerts`، ويخفي كذلك التنبيهات المخبأة عند فشل تحديث خلفي.
- **النطاق:** حالة خطأ عربية مدمجة مع إعادة المحاولة ورسالة الخادم الآمنة، مع إبقاء بيانات التنبيهات المخبأة ظاهرة. لا تغيير في عقد API.
- **معيار الخروج:** خمسة اختبارات واجهة تغطي النجاح مع تنبيهات، النجاح الفارغ، الفشل الأولي، فشل التحديث الخلفي مع بقاء البيانات، وإعادة المحاولة؛ Backend وFrontend وE2E وEncoding Guard وVercel خضراء.

### ✅ SEQ-21 — أحدث المرضى لا تعرض حالة فارغة أثناء التحميل
- **PR:** #658.
- **الدليل:** `frontend/src/app/(dashboard)/page.tsx` يبدأ `recentPatients` كمصفوفة فارغة بلا حالة تحميل مستقلة، فيعرض «لا يوجد مرضى بعد» بينما طلب `/api/patients?pageSize=5&status=active` ما زال معلقًا.
- **النطاق:** حالة تحميل مدمجة لقسم أحدث المرضى، مع إبقاء حالتي النجاح الفارغ والخطأ الحاليتين. لا تغيير في API أو وصول المرضى.
- **معيار الخروج:** اختبار ارتداد يؤخر استجابة المرضى ويثبت ظهور حالة التحميل وعدم ظهور الحالة الفارغة حتى نجاح الطلب؛ Backend وFrontend وE2E وEncoding Guard وVercel خضراء.

### ✅ SEQ-22 — فشل تحميل العقود لا يظهر كقائمة عقود فارغة
- **PR:** #659.
- **الدليل:** عند حجب `/api/finance-v3/contracts` في الإنتاج، تعرض تبويبة العقود رسالة «فشل في تحميل العقود» وفي الوقت نفسه «لا توجد عقود»، لأن `ContractsTab` لا يحتفظ بحالة خطأ مستقلة.
- **النطاق:** حالة خطأ عربية مدمجة مع إعادة المحاولة، ومنع الحالة الفارغة الكاذبة، وإبقاء بيانات العقود المخزنة ظاهرة عند فشل تحديث لاحق. لا تغيير في API أو الحسابات المالية.
- **معيار الخروج:** اختبارات واجهة تغطي الفشل الأولي، إعادة المحاولة، وفشل التحديث مع بقاء البيانات؛ Frontend وBackend وE2E وEncoding Guard وVercel خضراء.
