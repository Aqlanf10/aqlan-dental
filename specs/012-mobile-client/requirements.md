# 012 Mobile Client Requirements

هذه المواصفة تملك تطبيق الموظفين الأصلي داخل `mobile/`. وهي توسّع النظام القائم ولا
تنشئ API أو قاعدة بيانات أو صلاحيات موازية.

## المتطلبات

- `MOBILE-REQ-001` — SHALL يستهلك التطبيق واجهات ASP.NET Core الحالية وقاعدة البيانات
  الحالية فقط، مع بقاء تفويض الخادم هو المصدر النهائي للصلاحيات والوصول إلى المرضى.
- `MOBILE-REQ-002` — SHALL يستخدم تسجيل الدخول الأصلي مسارات
  `/api/auth/mobile/*` ويحفظ access/refresh tokens في مخزن بيانات الاعتماد الآمن للنظام،
  ولا يحفظ كلمة المرور.
- `MOBILE-REQ-003` — SHALL تكون كل الشاشات عربية وRTL، مع أهداف لمس واضحة، نص قابل
  للقراءة، ودعم الهواتف الصغيرة ولوحة المفاتيح.
- `MOBILE-REQ-004` — SHALL يعرض غلاف التطبيق هوية المركز الرسمية من
  `/api/public/website-settings` مع قيم احتياطية مطابقة لـ`MS-REQ-001`، ويستخدم الشعار
  الرسمي وألوان الهوية: `#1a3a5c`, `#3d7ab5`, `#f5922e`.
- `MOBILE-REQ-005` — SHALL يحتوي إصدار Android المستقل على JavaScript bundle مضمّن وأيقونة
  وشاشة بدء تحملان هوية المركز؛ ولا يعتمد إصدار Release على Metro.
- `MOBILE-REQ-006` — SHALL يلف جذر React Native بحاوية gesture آمنة، وألا يؤدي خطأ عرض
  JavaScript إلى إغلاق صامت؛ تعرض حدود الخطأ شاشة عربية قابلة للاسترداد وتتيح العودة الآمنة
  أو تسجيل الخروج.
- `MOBILE-REQ-007` — SHALL تميّز الشاشات بين التحميل والنجاح الفارغ والفشل، وتحتفظ
  بالبيانات المحملة عند فشل تحديث لاحق متى كان ذلك آمنًا.
- `MOBILE-REQ-008` — SHALL تمنع العمليات الحساسة النقر المتكرر أثناء التنفيذ، ولا تعيد
  تلقائيًا mutations قد تنشئ دفعة أو زيارة أو وصفة أو طلب معمل مكررًا.
- `MOBILE-REQ-009` — SHALL تبقي مساحات المرضى والمواعيد والتشغيل اليومي والسريري والمالية
  والتقويم والجراحة والمعمل والمخزون والتقارير والرسائل ضمن ملاك API الحاليين، بلا شاشات
  أو خدمات موازية.
- `MOBILE-REQ-010` — SHALL ينجح TypeScript وتصدير Android وiOS، ويُبنى APK Release مستقل
  قبل اعتباره جاهزًا للاختبار. الإغلاق الفعلي على جهاز حقيقي يبقى
  `Needs runtime verification` حتى يختبره المالك.

## معايير القبول للشريحة الحالية

1. عند فتح التطبيق يظهر شعار واسم وعنوان مركز د. عقلان، لا مربع `ADP` عام.
2. عند الضغط على تبويب أو إجراء تنقّل لا يغلق التطبيق بسبب غياب حاوية gestures.
3. عند حدوث خطأ عرض غير متوقع تظهر شاشة استرداد عربية بدل الإغلاق الصامت.
4. تعرض الرئيسية ملخص التشغيل وإجراءات سريعة بهرم بصري احترافي وبصلاحياتها الحالية.
5. يحمل شريط التبويب والترويسات وأيقونة التطبيق وشاشة البدء الهوية نفسها.
6. لا تتغير عقود API أو الأدوار أو الصلاحيات أو المخطط أو الحسابات المالية.
