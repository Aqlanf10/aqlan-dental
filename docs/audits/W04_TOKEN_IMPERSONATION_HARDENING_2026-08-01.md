# W04 — إصلاح دورة الرموز والانتحال وبوابة المريض

التاريخ: 2026-08-01

## السبب الجذري

كانت واجهة الموظفين تحفظ رمز الوصول الحالي ورمز المدير الأصلي داخل `localStorage`. وعند إنهاء الانتحال كانت تستعيد رمز المدير محليًا قبل استدعاء الخادم، لذلك يصل طلب `stop-impersonation` بهوية المدير العادية بدل رمز الانتحال الذي يحمل `originalUserId`. كان الخطأ يُبتلع، ويمكن أن تبقى مادة جلسة المدير قابلة للاستعادة بعد تسجيل الخروج أو إعادة تحميل الصفحة.

كذلك كانت دورة refresh للموظفين تنفذ `validate → revoke → store` كعمليات منفصلة في Redis، مما يسمح لنافذتين متزامنتين باجتياز التحقق بالرمز القديم قبل أن تحذفه إحداهما.

وفي بوابة المريض ظل `RefreshToken` موجودًا في DTO ويُرسل داخل JSON كمسار توافق قديم، رغم وجود كوكي `HttpOnly`.

## ما تم تنفيذه

1. نقل access token للموظفين إلى ذاكرة الوحدة فقط، مع تنظيف مفاتيح الإصدارات القديمة من `localStorage`.
2. إلغاء refresh token للمدير قبل بدء الانتحال، مع إبقاء access token القصير لإتمام عملية الانتحال وتسجيلها.
3. إبقاء كوكي الحساب المنتحل أثناء الجلسة حتى تعمل الصور والملفات؛ عند الإنهاء يُلغى refresh token للحساب المنتحل أولًا ثم يطلب access token المنتحل من الخادم جلسة مدير جديدة.
4. إذا انتهى access token أثناء الانتحال، لا يتحول إلى جلسة عادية للحساب المنتحل: تُستخدم عملية refresh مرة واحدة فقط للحصول على رمز قصير مخصص لاستدعاء logout وإبطال refresh token البديل، ثم يُطلب تسجيل دخول جديد.
5. عدم حفظ بيانات استعادة الانتحال داخل Zustand persistence؛ إعادة تحميل الصفحة أثناء الانتحال تتطلب تسجيل دخول جديدًا.
6. تدوير refresh token للموظفين ذريًا عبر Lua في Redis: استهلاك القديم وحذفه وحذف مفتاح مالكه وتخزين البديل ومفتاح مالكه في عملية واحدة.
7. تنظيف مفاتيح `refresh:owner:*` عند إبطال جميع جلسات المستخدم.
8. منع `PatientAuthResponse.RefreshToken` من JSON نهائيًا باستخدام `JsonIgnore`؛ يبقى للاستخدام الداخلي بين الخدمة والـcontroller لكتابة كوكي `portal_refresh` فقط.
9. تحديث اتصالات SignalR المشتركة لقراءة رمز الموظف من الذاكرة بدل `localStorage`.

## اختبارات الانحدار

- نجاح تدوير واحد فقط عبر عقد `RotateRefreshTokenAsync`.
- رفض إعادة استخدام رمز تم استهلاكه.
- التحقق من أن JSON الخاص ببوابة المريض لا يحتوي refresh token أو قيمته.
- حارس واجهة يمنع إعادة `access_token` أو `aqlan_original_token` إلى التخزين المحلي.
- حارس يثبت أن استعادة المدير تأتي بعد رد `stop-impersonation` من الخادم.

## حدود مقصودة

- جلسة الانتحال لا تُجدّد إلى جلسة عمل عادية. عند انتهاء access token أو إعادة تحميل الصفحة تُلغى الجلسة ويُطلب تسجيل دخول جديد، بدل فقد claims المدير الأصلي.
- يوجد اتصال SignalR محلي إضافي داخل شاشة الطابور ما زال يبحث عن المفتاح القديم؛ بعد هذا التغيير لا يجده وينتقل إلى polling الآمن. توحيده مع الخطاف المشترك تحسين منفصل، وليس مسار مصادقة أو تسريب رمز.
