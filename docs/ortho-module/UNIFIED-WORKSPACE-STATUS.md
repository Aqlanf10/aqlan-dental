## عرض الحالة PowerPoint — مكتمل ومطابق للسرد المرجعي
تسلسل الشرائح:
> غلاف (هوية المركز/الطبيب/المؤهل) ← بيانات المريض ← المقابلة/الشكوى ← صور خارج الفم ← التحليل الوجهي ← صور داخل الفم ← تقييم الإطباق ← بانوراما ← سيفالو + جدول القياسات ← تحليل النماذج ← بولتون ← **قائمة المشاكل (مُجمّعة بالفئة) ← التشخيص ← أهداف العلاج ← خطة العلاج** ← الميكانيكا ← **شريحة لكل زيارة ضبط (قصة العلاج زمنيًا)** ← صور التقدّم ← النتائج بعد العلاج ← **المقارنة قبل/بعد** ← الاحتفاظ ← الختام.

- الصور: تُستخدم النسخ المحضّرة (من المعالِج) بقص/تكبير/دوران/قلب/إضاءة/تباين مطبّقة فعليًا؛ WebP وغيرها تُحوَّل JPEG؛ crop-to-fill بلا تشويه.
- التذييل في كل شريحة: اسم المركز | التواصل | رقم الشريحة. كله من Settings بلا hardcoding.
- الواجهة: تبويب «التقارير» يعاين تسلسل الشرائح (جاهز/فارغ) ويتيح تضمين/استبعاد الفارغة قبل التنزيل.

## نقاط الـ API (كلها OrthoAccess + فحص وصول المريض)
- `GET /api/ortho-cases/{id}/case-summary/report/pdf`
- `GET /api/ortho-cases/{id}/model-analyses/latest|{id}/report/pdf`
- `GET /api/ortho-cases/{id}/case-presentation/definition`
- `POST /api/ortho-cases/{id}/case-presentation/pptx`
- `GET/PUT/DELETE /api/ortho-cases/{id}/photos/{photoId}/preparation`

## العمل المتبقّي (اختياري)
1. **توسعات عرض إضافية:** التراكب البنيوي وVTO كصور داخل العرض؛ تقسيم الميكانيكا لمراحل مستقلة (قلع/محاذاة/إغلاق/إنهاء)؛ تحليل الأثلاث/الأخماس كرسوم فوق الصورة الأمامية.
2. **hotfix الهجرات:** هجرتا `20260701`/`20260702` إضافيتان وصحيحتان، لكن بلا hotfix إقلاع idempotent على عرف المشروع. تطبّقهما `MigrateAsync` (مثل #379). توصية: إضافة `Ensure…SchemaAsync` احترازي مع الحذر الشديد من سلسلة الهجرات.
