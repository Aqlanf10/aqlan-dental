أنت بيئة التطوير الثانية لمشروع Aqlan Dental Pro الموجود في GitHub.

الهدف:
فحص نفس المشروع الحالي، تشغيله، إصلاح أخطائه، واستكمال وحداته من داخل نفس المستودع، دون إعادة بنائه من الصفر.

قواعد المستودع:

1. تحقق أولًا من:
   git remote -v
   git status
   git branch --show-current

2. يجب أن تعمل حصريًا على الفرع:
   replit-development

3. إذا لم يكن الفرع موجودًا، أنشئه من أحدث origin/main.

4. ممنوع:
   - تعديل main مباشرة.
   - git push origin main.
   - الدمج التلقائي.
   - حذف تاريخ Git.
   - force push.
   - إنشاء برنامج بديل منفصل.

5. يمكنك تنفيذ commits إلى replit-development بعد نجاح الفحوصات، لكن لا تنشئ Pull Request أو تدمج إلى main دون طلبي.

قواعد التقنية:

1. حافظ على الحزمة الأصلية:
   - Frontend: Next.js 15 + React 19.
   - Backend: ASP.NET Core .NET 8.
   - Database: PostgreSQL.
   - Redis عند الحاجة.

2. لا تحول Next.js إلى Vite.
3. لا تستبدل ASP.NET Core بـExpress أو Node.js.
4. لا تستبدل مكونات البرنامج بقوالب scaffold.
5. لا تغيّر قواعد العمل لمجرد تسهيل التشغيل على Replit.
6. حافظ على إمكانية تشغيل البرنامج خارج Replit.

قواعد قاعدة البيانات:

1. استخدم قاعدة PostgreSQL تطويرية مستقلة داخل Replit.
2. استخدم بيانات وهمية فقط.
3. ممنوع الاتصال بقاعدة Railway أو أي قاعدة إنتاجية.
4. ممنوع تنفيذ DROP أو reset أو migrations مدمرة دون تقرير وموافقة.
5. يجب أن تعمل جميع migrations على قاعدة نظيفة من الصفر.
6. أنشئ نسخة جديدة من قاعدة الاختبار عند التحقق النهائي، ولا تعتمد على قاعدة أُصلحت يدويًا أثناء التجارب.

طريقة العمل:

لا تعمل على أكثر من وحدة وظيفية واحدة في الوقت نفسه.

لكل وحدة:

1. اقرأ الواجهة والباك إند والكيانات والمهاجرات والاختبارات.
2. ارسم تدفق البيانات من الواجهة إلى API ثم قاعدة البيانات.
3. اكتب قائمة بالأخطاء والنواقص.
4. صنفها: حرجة، عالية، متوسطة، منخفضة.
5. اكتب معايير قبول واختبارات قبل الإصلاح.
6. أصلح الأسباب الحقيقية دون قمع أخطاء TypeScript أو C#.
7. اختبر الواجهة والـAPI وقاعدة البيانات والصلاحيات.
8. افحص Console وNetwork وBackend logs.
9. شغّل جميع الفحوصات.
10. أنشئ Checkpoint.
11. نفّذ commit واضحًا ومحدود النطاق.
12. قدم تقريرًا وتوقف قبل الوحدة التالية.

الفحوصات الإلزامية:

Backend:
- dotnet restore
- dotnet build
- dotnet test

Frontend:
- npm أو pnpm install حسب lockfile الأصلي
- typecheck
- lint إن كان مهيأ
- test
- build

Integration:
- تشغيل PostgreSQL وRedis وASP.NET Core وNext.js.
- GET /health.
- تسجيل الدخول الحقيقي.
- قراءة وكتابة بيانات وهمية.
- اختبار 401 و403 و404 و500.
- تحديث الصفحة داخل المسارات الداخلية.
- التأكد من عدم وجود أخطاء غير معالجة.

معيار إكمال الوحدة:

لا تعتبر الوحدة مكتملة بسبب ظهور الصفحة.

يجب أن:
- تعمل من الواجهة.
- تتصل بالـAPI الحقيقي.
- تحفظ وتقرأ من PostgreSQL.
- تطبق الصلاحيات في الواجهة والباك إند.
- تمنع التكرار عند إعادة المحاولة أو الضغط مرتين.
- تتعامل مع الأخطاء.
- تنجح اختبارات البناء والوحدة والتكامل.
- تعمل على الكمبيوتر والهاتف.

ابدأ الآن بمرحلة Baseline فقط:

1. مزامنة replit-development مع أحدث main.
2. تشغيل الحزمة الأصلية كاملة.
3. إنشاء قاعدة تطوير نظيفة.
4. تشغيل migrations من الصفر.
5. تشغيل جميع الاختبارات.
6. اختبار تسجيل الدخول.
7. جرد جميع الوحدات والمسارات والـAPI endpoints.
8. إنشاء ملف داخل docs باسم:
   REPLIT_DEVELOPMENT_STATUS.md

يحتوي الملف على:
- حالة كل وحدة.
- الأخطاء المعروفة.
- الأزرار أو الصفحات الشكلية.
- الاختبارات الموجودة والناقصة.
- الاعتماديات بين الوحدات.
- أولويات التطوير.
- آخر commit ناجح.
- قاعدة البيانات المستخدمة.
- المهمة الحالية فقط.

بعد تقرير Baseline، توقف وانتظر مني تحديد أول وحدة.
لا تقترح تطبيق هاتف أو فيديو أو عرضًا تقديميًا.
