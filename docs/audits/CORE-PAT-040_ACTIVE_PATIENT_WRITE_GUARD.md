# CORE-PAT-040 — Active-patient write guard

## المشكلة

كانت عدة مسارات إنشاء تقبل `PatientId` لملف غير موجود أو مؤرشف، فتسمح بإنشاء صور وأشعة وأوامر مختبر وعقود ودفعات وحالات تقويم بلا ملف مريض فعال.

## المعالجة

- إضافة `ActivePatientWriteGuard` كمرجع واحد للتحقق من وجود مريض فعال.
- الاعتماد على مرشح الحذف الناعم القانوني في `AppDbContext`، لذلك يُرفض المريض المؤرشف تلقائيًا.
- حماية الصور والأشعة وأوامر المختبر داخل المتحكمات التي تستقبل المعرّف في جسم الطلب.
- فرض الحارس داخل خدمات العقود والدفعات والتقويم ليشمل جميع المستدعين.
- تحويل رفض إنشاء حالة التقويم إلى استجابة 400 عربية واضحة بدل خطأ خادم.

## الاختبارات

- قبول المريض النشط.
- رفض المريض المؤرشف عبر مرشح EF الفعلي.
- رفض المعرّف الفارغ أو غير الموجود.
- عقد يحمي جميع نقاط الكتابة التي أضيف إليها الحارس.

## النطاق

لا توجد ترحيلات أو تغييرات قاعدة بيانات؛ التغيير تحقق قبل الكتابة فقط.

## ملاحظة النشر

تجاوز مشروع Vercel حد عمليات النشر اليومية؛ يعتمد قبول التغيير على CI الكامل إلى أن تتجدد الحصة الخارجية.
