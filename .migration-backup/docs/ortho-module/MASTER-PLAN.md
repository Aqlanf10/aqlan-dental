# Orthodontic Module — Master Plan (وحدة التقويم الاحترافية)
**أُقرّت من المالك 2026-06-12** · المرجع الكامل للمواصفات في طلب المالك (محفوظ هنا مكثّفًا) · **قاعدة ذهبية: البناء فوق وحدة التقويم الموجودة (`OrthoCases` وملحقاتها) — لا إعادة بناء ولا عزل**

## الرؤية
مساحة عمل سريرية مركزية لمرضى التقويم بمستوى WebCeph/Dolphin، **مدمجة بعمق** مع: ملف المريض، العمليات اليومية، عيادة الطبيب، المواعيد، المالية V3 (مصدر الحقيقة)، المختبر، وPDF.

## ما هو موجود اليوم (لا يُكرر)
`OrthoCase` + تبويبات: Overview, Records Checklist, Clinical Exam, Problem List, Diagnosis, Treatment Plans, Stages (+timeline), Visits (+timeline), Extraction Decision, Retention, Finance, Photos (+before/after compare), CephAnalyses/CephLandmarks/CephMeasurements/CephDiagnoses entities, ModelAnalyses entity, عقود مالية مرتبطة (`RelatedCaseId`), أوامر مختبر مرتبطة (`OrthoCaseId`).

## المراحل (كل مرحلة = PR مستقل قابل للاختبار)
| المرحلة | النطاق | الحالة |
|---|---|---|
| **P1 — تكامل أفقي** | قسم تقويم في ملف المريض (الحالة النشطة، المرحلة، الموعد القادم، ملخص العقد، زر فتح مساحة العمل) + شارة/معلومات الحالة التقويمية في العمليات اليومية وشاشة الطبيب + أنواع زيارة تقويمية في المواعيد (Bonding/Adjustment/Debonding/Retainer...) مربوطة بـ OrthoCaseId | ⬜ التالي |
| **P2 — السجلات والصور القياسية** | فئات الصور القياسية (خارج/داخل الفم/أشعة/مستندات) فوق `ClinicalPhotos`/مرفقات موجودة، وسم قبل/أثناء/بعد، شبكة معاينة + عارض، اختيار صور التقارير | ⬜ |
| **P3 — الفحص السريري المنظّم** | توسيع `OrthoClinicalExam`: خارج الفم (نمط عمودي/ابتسامة/شفاه/عادات)، داخل الفم، الإطباق (مولار/ناب/قواطع يمين-يسار، overjet/overbite mm، crossbite، midline، crowding/spacing mm، Bolton حقل) | ⬜ |
| **P4 — تحليل النماذج** | Space analysis + Bolton (نِسَب أمامية/كلية + تفسير) + Moyers/Tanaka-Johnston + Pont + Ashley Howe — شبكة إدخال FDI، حساب تلقائي + override، بطاقة نتيجة ملونة، PDF | ⬜ |
| **P5 — السيفالومتري اليدوي** | رفع + معايرة مسطرة، وضع معالم يدوي (canvas موجود جزئيًا في components/ceph)، Steiner/Tweed/Downs/Wits/McNamara/Soft tissue، **جدول قيم معيارية دولية قابل للتهيئة** (Mean/SD/Min/Max/تفسير أعلى-أدنى)، تفسير ملون، إصدارات ومقارنة قبل/تقدم، PDF عربي/إنجليزي | ⬜ |
| **P6 — محرك التشخيص القاعدي** | Rule-engine من القياسات: تصنيف هيكلي I/II/III، النمط العمودي، ميل القواطع، مؤشرات قلع/جراحة — **بدون AI مزيف**؛ ينتج Problem List + Diagnosis draft قابلة للتحرير | ⬜ |
| **P7 — خطة العلاج الموسعة** | خيارات A/B/C بمزايا/عيوب/مخاطر/مدة/تكلفة + خطة قلع/إرساء/أقواس/IPR/مطاطات/إحالات + أهداف علاجية منظمة | ⬜ |
| **P8 — الزيارات والأجهزة** | حقول زيارة تقويمية (أسلاك علوي/سفلي، مطاطات، power chain، حاصرات مكسورة، نظافة فم، خطة الزيارة القادمة) + تتبع الأجهزة (slot/prescription/bonding/debonding/retainer) + ربط الزيارة بالعمليات اليومية | ⬜ |
| **P9 — مالية وعقد التقويم** | عرض العقد داخل الحالة من Finance V3 (لا منطق مكرر): إجمالي/مقدم/قسط/متبقي/متأخر + تنبيه قسط مستحق في العمليات اليومية + PDF عقد وجدول أقساط | ⬜ |
| **P10 — مساعد AI آمن** | مسودات (تشخيص/أهداف/بدائل/شرح للمريض/عرض حالة/إحالة) من **البيانات المنظمة فقط** عبر Claude API، جدول تدقيق `OrthodonticAiLogs` (قبول/تعديل/رفض)، عبارة إلزامية: «مسودة AI تتطلب مراجعة أخصائي التقويم»، مفتاح تشغيل من الإعدادات | ⬜ |
| **P11 — عرض الحالة Case Presentation** | مولّد PDF بأقسام قابلة للاختيار وإعادة الترتيب (شرائح العرض الأكاديمي 1-15)، نسخ عربي/إنجليزي/أكاديمي/مبسط | ⬜ |
| **P12 — جاهزية مستقبلية** | واجهة `POST /api/orthodontics/ceph/auto-trace` placeholder بـ«يحتاج تفعيل نموذج متقدم»، بنية superimposition وVTO بدون حسابات مزيفة | ⬜ |

## قواعد ثابتة (من المالك)
- مفاتيح صلاحيات `Orthodontics.*` عبر RolePermissions — لا hardcoding.
- إعدادات قابلة للتهيئة: فاصل المتابعة الافتراضي 21 يوم، رسوم الاستشارة 3000 YER، قيم سيفالومترية معيارية، بروتوكولات احتفاظ، يتطلب موافقة طبيب لمخرجات AI، يتطلب خلوص مالي قبل debonding (نعم/لا).
- لا حذف حالة لها سجلات — أرشفة فقط. كل تغيير حالة Status مسجّل تدقيقيًا.
- الأرقام السنية FDI. كل PDF عربي RTL بهوية المركز.
- اختبارات لكل مرحلة + smoke حي قبل أي PR.
