# SpecKit في Aqlan Dental Pro

SpecKit هنا يعني أن التطوير لا يبدأ من تخمين نموذج ذكاء اصطناعي، بل من مواصفة واضحة مرتبطة بالكود الفعلي.

هذا النظام موجود لأن Aqlan Dental Pro كبير وحساس: مرضى، صلاحيات، مالية، تقويم، سيفالومتري، مختبر، مخزون، تقارير، وإعدادات إنتاج. أي نموذج يمكن أن يضيف شاشة مكررة أو خدمة وهمية إذا لم يعرف أين يعيش كل شيء.

## لماذا يوجد؟

- يمنع تكرار dashboard أو control panel.
- يمنع إنشاء routes أو controllers موازية.
- يحمي المالية والصلاحيات وبيانات المرضى.
- يجبر كل PR أن يذكر Spec ID.
- يعطي النماذج الصغيرة وضعا آمنا للقراءة والتقارير فقط.

## كيف تستخدمه؟

قبل أي مهمة:

1. اقرأ `.specify/constitution.md`.
2. اقرأ `specs/000-master-system/module-map.md`.
3. اختر spec الميزة المناسبة من `specs/001` إلى `specs/009`.
4. إذا لم توجد مواصفة للمطلوب، حدّث أو أنشئ المواصفة أولا.
5. نفذ مهمة صغيرة واحدة فقط.
6. حدّث traceability إذا تغير السلوك.

## مع النماذج المختلفة

- Claude Code: مناسب للهندسة، المراجعات المعقدة، PRs، والقرارات الحساسة.
- Codex: مناسب للتنفيذ والاختبارات مع الالتزام بالSpec.
- Gemini: مناسب للتحليل، التخطيط، مراجعة UI، والتلخيص.
- OpenCode: مناسب للمهام المحددة داخل ملفات واضحة.
- النموذج الرخيص: قراءة، تلخيص، checklist، تقارير، واقتراح اختبارات فقط إلا إذا سمح الملف صراحة.

القاعدة المختصرة: لا تنفيذ بدون Spec.
