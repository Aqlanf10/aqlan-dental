# طابور السبرنتات الإلزامي — Mandatory Sprint Queue

**هذا الملف هو مصدر الحقيقة الوحيد لترتيب العمل على Aqlan Dental Pro.**
يلغي أي ترتيب سابق في ملفات الخطط التاريخية. الأدلة التفصيلية تبقى في
`docs/governance/SPEC_TO_CODE_TRACEABILITY.md` وملفات التدقيق والـPRs المرتبطة.

## القاعدة الإلزامية

1. قبل أي تطوير، اقرأ هذا الملف كاملًا.
2. أول عنصر بحالة `🔴 محجوب` أو `🟡 جاهز` أو `🔵 قيد التنفيذ` هو العمل الوحيد المسموح.
3. لا يجوز القفز لعنصر لاحق إلا لحادث إنتاج P0، تدقيق قراءة فقط، إكمال PR مفتوح، أو حل تعارض دمج.
4. كل PR تنفيذي يذكر رقم العنصر في العنوان، ويحدّث حالته عند تحقق معيار الخروج.
5. البنود المنجزة لا يعاد فتحها إلا بدليل ارتداد أو عطل إنتاجي جديد.

- تعرض شاشة التفاصيل الملاحظات السريرية المحفوظة، وتفك غلاف JSON الخاص بالمعايرة بدل إظهار البيانات الخام.
- يظهر وسم واضح للتحليل الناتج من التتبع الآلي مع اشتراط مراجعة الطبيب.
- **معيار الخروج:** اختبارات type/render تغطي النص العادي، JSON المغلف، الحالة الفارغة، ووسم التتبع الآلي؛ لا schema أو API أو تعديل سريري تلقائي.

### ✅ SEQ-15 — تصحيح دلالة ملاحظات السيفالو عند حد DTO
- **PR:** #651.
- أصبح `CephAnalysisDetailDto.Notes` يعيد الملاحظة السريرية فقط بدل غلاف JSON الداخلي للمعايرة.
- يدعم النصوص القديمة و`UserNotes` بصيغتي PascalCase/camelCase، ويعيد `null` للغلاف الخالي دون تعديل القيمة المخزنة.
- **معيار الخروج:** Backend وFrontend وE2E وEncoding Guard خضراء، واختبارات الخدمة/DTO تغطي النص القديم والغلاف والحالة الفارغة وJSON غير المكتمل، دون schema أو endpoint change.

### ✅ SEQ-16 — منع الحالة الفارغة الكاذبة في عيادة الطبيب
- **PR:** #652.
- فشل التحميل الأول لقائمة مرضى عيادة الطبيب يعرض شاشة خطأ عربية واضحة بدل «لا يوجد مرضى» الكاذبة.
- فشل التحديث الدوري بعد وجود بيانات لا يهدم مساحة الطبيب ولا يفقد الملاحظات السريرية غير المحفوظة؛ تبقى البيانات المخزنة ظاهرة.
- **معيار الخروج:** الاستجابة الناجحة الفارغة، والفشل الأولي، وفشل التحديث الخلفي مغطاة باختبارات ارتداد؛ Backend وFrontend وE2E وEncoding Guard خضراء، وملاحظة Codex P2 محلولة، ولا API أو schema أو تغيير في سير الزيارة.

### ✅ SEQ-17 — كشف حساب الطبيب غير المرتبط بسجل طبيب
- **PR:** #653.
- الحساب السريري غير المرتبط بـ`doctorId` لا يرسل طلب قائمة مرضى ولا يعرض «لا يوجد مرضى» الكاذبة، بل تظهر له رسالة إعداد عربية تطلب من المدير ربط الحساب من إعدادات المستخدمين والصلاحيات.
- بقي وضع Admin لعرض جميع الأطباء، وبقي الحساب المرتبط يرسل `doctorId` الصحيح دون تغيير في الوصول أو سير الزيارة.
- **معيار الخروج:** اختبارات الواجهة تغطي الحساب غير المرتبط، الحساب المرتبط، ورسالة الإصلاح؛ Frontend وBackend وE2E وEncoding Guard خضراء، ولا API أو schema أو auth DTO أو ربط تلقائي.

### 🔵 SEQ-18 — إثراء استجابة إنشاء الموعد
- **المشكلة المؤكدة:** `AppointmentService.CreateAsync` يحوّل كيان الموعد الجديد مباشرة إلى DTO بعد الحفظ، بينما علاقات `Patient` و`Doctor` غير محملة، فتعود `patientName` و`doctorName` فارغتين رغم نجاح الإنشاء.
- **النطاق:** تحميل علاقات العرض داخل معاملة إنشاء الموعد قبل الإرجاع، دون تغيير request/response schema أو قواعد الحجز أو الصلاحيات.
- **معيار الخروج:** استجابة الإنشاء تحتوي اسم المريض والطبيب الصحيحين، وتبقى حماية التعارض الذرية كما هي، مع اختبار ارتداد يثبت تحميل العلاقات وكل الفحوصات خضراء.
