# Development Roadmap — Aqlan Dental Pro

> **مؤرشف (سجل تاريخي فقط).** لا يُستخدم هذا الملف لتحديد ترتيب العمل بعد الآن —
> بعض بنوده أُنجز فعلًا (مثل Sprint B تعيينات غرف الأطباء) وبعضها تجاوزته الأحداث.
> الطابور الملزم الحالي هو `docs/governance/MANDATORY_SPRINT_QUEUE.md` — اقرأه أولًا.

**التاريخ:** 2026-06-12 · بعد جولة الصيانة والتثبيت (تاريخي)

النظام في حالة إنتاجية جيدة: البناء أخضر، 1318 اختبار باك إند + 84 اختبار واجهة كلها ناجحة، والرحلة اليومية والمالية V3 وPDF تعمل. الخارطة التالية مرتبة حسب الأثر التشغيلي:

## Sprint A — أمان الجلسات (أسبوع)
1. نقل refresh token لبوابة المرضى إلى HTTP-only cookie (نفس نمط الموظفين).
2. (اختياري) access token للموظفين in-memory بدل localStorage.
3. اختبارات للتدفقين.

## Sprint B — غرف الأطباء (أسبوع)
1. كيان `DoctorRoomAssignment` (DoctorId, RoomId, BranchId, IsActive).
2. فلترة قائمة الانتظار/الرحلة بحسب غرف الطبيب (Admin يرى الكل).
3. إدارة التعيينات من شاشة الإعدادات.

## Sprint C — الإعدادات الموحدة (أسبوعان)
توسيع جدول `Settings` وواجهته لتغطية: رسوم الكشف، حد خصم الطبيب، قواعد العمولات، قاعدة خصم المختبر، `finance.prevent_negative_treasury_balance` (مُنفّذ هذا السبرنت على مستوى DB)، بيانات العيادة وتخطيط السند، ساعات العمل، أنواع المواعيد، أسماء الغرف، أسعار الخدمات. مبدأ: لا قيم مالية ثابتة في الكود.

## Sprint D — تحسين تجربة العمليات اليومية (أسبوعان)
1. SignalR مباشر في شاشة الرحلة بدل الاستطلاع كل 60 ثانية.
2. شريط أوامر علوي + بطاقات حالة اليوم (المنتظرون/في الغرف/جاهزون للتحصيل/مكتملون).
3. تقليل النقرات: إجراءات سريعة من بطاقة المريض.
4. تقرير العمليات اليومية PDF.

## Sprint E — تفكيك الملفات الضخمة + تغطية اختبارات (أسبوعان)
1. تقسيم `PatientJourneyController` إلى partials حسب المرحلة.
2. اختبارات تكامل لآلة حالات الرحلة (intake→checkout).
3. اختبارات refund↔commission والتدفقات المتزامنة.

## Sprint F — مختبر متقدم (أسبوع)
1. شاشة متابعة أوامر متأخرة (موجودة جزئيًا) + تنبيهات.
2. مرفقات صور/STL (الكيان موجود — استكمال الواجهة).
3. ربط أعمق بين LabPayable وتقارير المصروفات.

## مبادئ ثابتة لكل سبرنت
- لا حذف ميزات أو هجرات. عمل تزايدي على فروع. اختبارات لكل إصلاح. رسائل خطأ عربية واضحة. التزام RTL.
