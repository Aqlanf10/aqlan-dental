توضيح نهائي للمطلوب:

أريدك أن تعمل على نفس مشروع Aqlan Dental Pro الموجود في GitHub، وليس إنشاء برنامج جديد أو نسخة معاد بناؤها بتقنيات مختلفة.

المطلوب هو:

1. استيراد مستودع GitHub كاملًا بكل ملفاته ومجلداته:

   * الواجهة الأصلية Next.js.
   * الباك إند الأصلي ASP.NET Core.
   * ملفات قاعدة البيانات والترحيلات.
   * الاختبارات.
   * الوثائق.
   * إعدادات المشروع.
   * جميع الوحدات الموجودة حاليًا.

2. اجعل نسخة GitHub المستوردة هي المشروع الأساسي داخل Replit.

3. لا تعِد كتابة البرنامج من البداية باستخدام Vite أو Express أو أي Stack جديد.

4. لا تستبدل الباك إند ASP.NET Core بباك إند Node.js.

5. لا تحوّل Next.js إلى Vite لمجرد ملاءمة Artifact جاهز. حاول أولًا تشغيل المشروع الأصلي داخل بيئة Replit بإعدادات تشغيل مخصصة.

6. استخدم ملف .replit وWorkflows وأوامر Shell لتشغيل الواجهة والباك إند الأصليين.

7. إذا كانت هناك مشكلة تمنع تشغيل تقنية معينة داخل Replit:

   * حدد المشكلة بدليل تقني واضح.
   * اشرح أقل تعديل ممكن لحلها.
   * لا تنفذ تغييرًا معماريًا واسعًا قبل تقديم التقرير.
   * حافظ على منطق البرنامج وواجهاته ومساراته وقواعد العمل كما هي.

8. لا تنشئ برنامجًا موازيًا أو صفحات جديدة منفصلة عن المشروع الأصلي.

9. لا تستخدم scaffold أو boilerplate بديلًا بدل مكونات البرنامج الأصلية.

10. احتفظ بجميع مكونات المشروع الأصلية، ولا تحذف أي ملف إلا بعد إثبات أنه غير مستخدم وعرض سبب الحذف.

11. استخدم فرع Git مستقل باسم:
    replit-development

12. لا تعدّل فرع main ولا تدمج إليه تلقائيًا.

13. اربط فرع Replit بمستودع GitHub نفسه حتى يمكن مراجعة جميع التغييرات وإعادتها إلى المشروع الأساسي لاحقًا.

14. استخدم قاعدة بيانات تجريبية منفصلة وبيانات وهمية فقط أثناء التطوير.

15. لا تتصل بقاعدة بيانات العيادة الإنتاجية، ولا تستخدم بيانات مرضى حقيقية.

16. لا تنفذ migrations مدمرة أو reset أو حذف بيانات دون عرض خطة التأثير أولًا.

17. بعد استيراد المشروع، نفذ جردًا شاملًا يوضح:

* بنية المستودع.
* طريقة تشغيل الواجهة.
* طريقة تشغيل الباك إند.
* متغيرات البيئة المطلوبة.
* اتصال PostgreSQL.
* الاختبارات الموجودة.
* الوحدات المكتملة.
* الوحدات الناقصة.
* أخطاء البناء والتشغيل الحالية.

18. شغّل المشروع الأصلي أولًا قبل إضافة ميزات جديدة:

* تثبيت الاعتماديات.
* تشغيل Next.js.
* تشغيل ASP.NET Core.
* الاتصال بقاعدة PostgreSQL التجريبية.
* تشغيل migrations الآمنة.
* فتح صفحة تسجيل الدخول.
* اختبار الاتصال الحقيقي بالـAPI.

19. شغّل جميع الفحوصات الموجودة في المستودع:

* build للواجهة.
* typecheck.
* lint إن كان موجودًا.
* اختبارات الواجهة.
* dotnet restore.
* dotnet build.
* dotnet test.
* فحص Console وNetwork وLogs.

20. بعد تشغيل المشروع، ابدأ تطويره وإصلاحه من داخل نفس الكود، وحدة بعد وحدة، بهذا الترتيب:

* تسجيل الدخول والصلاحيات.
* الإعدادات والهوية.
* المرضى.
* المواعيد والعمليات اليومية.
* عيادة الطبيب.
* المالية والصندوق.
* المختبر.
* التقارير والطباعة.
* التقويم والسيفالومتري.

21. في كل وحدة:

* افحص الكود الموجود أولًا.
* حافظ على الوظائف المكتملة.
* اكتشف الأخطاء والنواقص.
* اكتب حالات اختبار.
* أصلح السبب الحقيقي للخطأ.
* اربط الواجهة بالباك إند وقاعدة البيانات.
* اختبر الصلاحيات.
* اختبر حالات الفشل.
* شغّل الاختبارات والبناء.
* أنشئ checkpoint.
* اعرض تقريرًا بالملفات المعدلة.

22. لا تعتبر تصميم الصفحة أو ظهورها بصريًا إنجازًا كاملًا. الوحدة لا تعتبر مكتملة إلا عندما تعمل:

* من الواجهة.
* عبر API الحقيقي.
* داخل قاعدة البيانات.
* مع الصلاحيات.
* مع الاختبارات.
* دون أخطاء Console أو Network غير معالجة.

23. لا تغيّر أسماء المسارات أو قواعد العمل أو تصميم النظام بشكل جذري فقط لتسهيل النقل إلى Replit.

24. حافظ على توافق المشروع مع GitHub وإمكانية تشغيله خارج Replit. لا تجعل الكود مرتبطًا حصريًا بمنصة Replit.

25. لا تبدأ من مشروع فارغ، ولا تنشئ Aqlan Dental Pro جديدًا. المطلوب تطوير نفس المستودع الحالي وإنهاؤه داخل بيئة Replit.

ابدأ الآن بالآتي:

أولًا: تأكد أن جميع ملفات GitHub الأصلية موجودة داخل مساحة العمل.

ثانيًا: قارن الملفات الحالية مع النسخة الأصلية في GitHub وحدد أي ملفات تم تحويلها أو حذفها أو استبدالها خلال محاولة Vite السابقة.

ثالثًا: استعد المشروع الأصلي من GitHub أو من .migration-backup عند الحاجة، مع عدم فقد أي إصلاح صحيح يمكن نقله بأمان.

رابعًا: جهز تشغيل الواجهة Next.js والباك إند ASP.NET Core داخل Replit.

خامسًا: قدم تقرير تشغيل حقيقي، ثم ابدأ إصلاح المشروع واستكماله من نفس الكود.

الهدف النهائي:
أن يصبح نفس مشروع GitHub الحالي قابلًا للتشغيل والتطوير والاختبار داخل Replit، وأن يقوم Replit Agent بإكمال البرنامج وإصلاح أخطائه بصورة أسرع، دون إعادة بنائه من الصفر.
