# CORE-PAT-025 — سجل مدفوعات المريض الكامل

## العطل

كانت هناك نقطتا قطع مستقلتان عند 20 سجلًا:

1. `PaymentsTab` يستدعي `GET /api/payments?patientId=...` دون تحديد الصفحة، فيستخدم الخادم `page=1&pageSize=20`.
2. كشف حساب المريض ينفذ `Take(20)` قبل بناء `RecentPayments`.

لذلك لا يرى الموظف الدفعة رقم 21 وما بعدها داخل ملف المريض، رغم أن الإجماليات المالية تحسب جميع الدفعات.

## الإصلاح

- إضافة `GET /api/patients/{patientId}/payments` لإرجاع كل المدفوعات النشطة لمريض واحد، مع احترام صلاحية `finance.payments.view` ونطاق الفرع.
- إبقاء endpoint المالية العامة مرقّمًا كما هو لحماية الأداء في القوائم العامة.
- إضافة `Payments` و`TotalPaymentsCount` إلى كشف الحساب.
- إبقاء `RecentPayments` لأول 20 سجلًا للتوافق مع العملاء القديمة أثناء النشر المرحلي.
- تحديث `PaymentsTab` لاستخدام endpoint المريض الكامل.
- تحديث `FinanceTab` لعرض «سجل المدفوعات» الكامل، مع fallback إلى `RecentPayments` إذا كان الخادم القديم ما يزال يعمل.

## اختبارات منع الرجوع

- زرع 25 دفعة نشطة ودفعة غير نشطة؛ endpoint المريض يعيد 25 فقط بترتيب الأحدث.
- كشف الحساب يعيد `Payments = 25` و`TotalPaymentsCount = 25` مع `RecentPayments = 20` للتوافق.
- واجهة الملف تعرض الدفعة رقم 25 وجميع السجلات الخمسة والعشرين.
